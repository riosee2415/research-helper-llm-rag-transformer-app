# Architecture Decision Records

## 철학
정확성 최우선. 전문 연구자 대상이므로 창의적 답변보다 근거 있는 정확한 답변이 가치 있다.
의존성은 안정적인 오픈소스(LangChain, Pinecone)에 위임하고 비즈니스 로직에 집중한다.
에러 처리는 격리 원칙: 한 컴포넌트 실패가 전체 시스템을 다운시키지 않는다.

---

### ADR-001: LangChain 선택 (vs 직접 구현)
**결정**: RAG 오케스트레이션에 LangChain을 사용한다.
**이유**: ConversationalRetrievalChain, ConversationBufferMemory, StuffDocumentsChain 등 필요한 구조가 이미 구현되어 있다. 직접 구현 대비 코드량과 버그 리스크를 줄인다.
**트레이드오프**: LangChain 버전 업그레이드 시 API 변경 위험. 내부 동작을 세밀하게 제어하기 어려울 수 있다.

### ADR-002: text-embedding-3-large 선택
**결정**: 임베딩 모델로 `text-embedding-3-large` (dim 3072)를 사용한다.
**이유**: 기술·특허 문서의 전문 용어와 의미적 유사도를 높은 정밀도로 포착. Pinecone 인덱스 설정(dim 3072)과 일치.
**트레이드오프**: `text-embedding-3-small` 대비 비용 높고 속도 느림.

### ADR-003: 2-chain 구조 (응축 + QA 분리)
**결정**: 질문 응축(Chain-1)과 QA(Chain-2)를 별도 체인으로 분리한다.
**이유**: 연속 질문의 지시어("이거", "그게")가 있으면 리트리버가 적절한 문서를 찾지 못한다. Chain-1이 독립형 질문으로 재작성하면 검색 정확도가 높아진다.
**트레이드오프**: LLM 호출 2회 → 응답 시간, 비용 증가.

### ADR-004: 한국어 고정 답변
**결정**: 질문 언어와 무관하게 항상 한국어로 답변한다.
**이유**: 대상 사용자가 한국어 사용자. 단일 언어 고정으로 프롬프트 일관성 및 품질 확보.
**트레이드오프**: 영어 질문에 한국어 답변이 어색할 수 있다.

### ADR-005: 파일 해시 기반 중복 방지
**결정**: 인제스트 시 파일 MD5 해시를 Pinecone 메타데이터에 저장, 재실행 시 중복 업로드 방지.
**이유**: PDF가 지속적으로 추가되는 환경에서 `ingest.py` 반복 실행 시 멱등성 필요.
**트레이드오프**: 파일 내용 변경 시 기존 청크 자동 삭제 없음 → 수동 정리 필요.

### ADR-006: pdfplumber 선택 (vs pypdf, pymupdf)
**결정**: PDF 파싱에 pdfplumber를 사용한다. pypdf는 사용하지 않는다.
**이유**: 특허·학술 논문의 다단 레이아웃(2-column IEEE, 특허 청구항 등)에서 pypdf보다 컬럼 순서를 정확히 복원한다. 위치 기반 텍스트 추출이라 테이블 텍스트도 더 자연스럽다. MIT 라이선스로 제약 없음.
**pymupdf 미선택 이유**: AGPL 라이선스. 속도는 빠르지만 라이선스 리스크가 있다.
**트레이드오프**: pymupdf 대비 느림. 복잡한 수식·벡터 그래픽 처리 불가.

### ADR-007: 지수 백오프 재시도 전략
**결정**: OpenAI API 오류 시 지수 백오프 최대 3회 재시도한다. 대기: 1s, 2s, 4s.
**이유**: OpenAI의 RateLimitError(429)는 일시적이며 대기 후 성공률이 높다.
**비재시도 대상**: AuthenticationError, PermissionDeniedError, APIConnectionError — 이 오류는 재시도로 해결되지 않는다.
**트레이드오프**: 최대 7초 추가 대기. 비재시도 오류와 명확히 구분 필요.

### ADR-008: 유사도 임계값 0.3 설정 (실측 기반 조정)
**결정**: Pinecone 검색 결과 중 cosine similarity < 0.3인 청크는 사용하지 않는다.
**이유**: `text-embedding-3-large`로 한국어 기술 문서를 임베딩하면 Pinecone cosine 기준 관련 문서의 실측 점수가 0.40~0.55 범위다. 초기 설정값 0.7은 모든 결과를 차단했다. 0.3은 관련 문서를 통과시키면서 무관한 문서(실측 0.2 이하)를 걸러낸다.
**트레이드오프**: 0.3은 0.7보다 관대하므로 낮은 관련성 문서가 포함될 수 있다. 그러나 QA 모델이 컨텍스트 기반으로만 답변하므로(rule 1) 실질적 할루시네이션 리스크는 낮다. 필요 시 config.py의 `SIMILARITY_THRESHOLD`로 조정 가능.

### ADR-009: LLM Temperature 0.0 (결정론적 응답)
**결정**: 모든 LLM 호출에 `temperature=0.0`을 사용한다.
**이유**: 연구자는 재현 가능한 답변을 기대한다. Temperature가 높으면 동일 질문에 다른 답변이 나와 신뢰도가 하락한다.
**트레이드오프**: 창의적 표현 없음. 동일 컨텍스트에 동일 답변이 반복됨.

### ADR-010: ConversationBufferMemory + 토큰 한도 트리밍
**결정**: 대화 히스토리 저장에 ConversationBufferMemory를 사용하되, MAX_MEMORY_TOKENS(4000) 초과 시 오래된 메시지를 제거한다.
**이유**: 무제한 히스토리 누적은 gpt-4o 컨텍스트 윈도우 초과로 이어진다. 트리밍으로 안정적 세션 유지.
**트레이드오프**: 긴 세션에서 초기 질문 맥락 소실 가능. tiktoken 의존성 추가.

### ADR-011: 파일명 무관 전체 PDF 인제스트
**결정**: rag_data/ 디렉토리 내 모든 PDF 파일을 인제스트한다. 파일명은 필터링하지 않는다.
**이유**: 논문·특허 파일명은 규칙적이지 않을 수 있다. 특정 파일명 패턴을 하드코딩하면 새 파일이 누락될 수 있다. rag_data/에 들어가는 모든 파일은 관련 연구·특허 자료로 간주한다.
**구현**: `glob.glob(os.path.join(dir_path, "**", "*.pdf"), recursive=True)` — 하위 폴더 포함, 대소문자 무관 처리.
**트레이드오프**: 실수로 넣은 PDF도 인제스트됨. 사용자가 rag_data/ 관리 책임.

### ADR-013: 로컬 파일 기반 세션 영속화 (로그인 없음)
**결정**: 대화 히스토리를 `data/sessions/` 폴더의 JSON 파일로 저장한다. 사용자 인증 없음.
**이유**: 단일 PC에서 사용하는 연구 도구이므로 로그인이 불필요하다. 파일 기반 저장은 외부 의존성이 없고 구현이 단순하다. 앱 재시작 후에도 이전 대화를 복원할 수 있어 연속 연구 작업을 지원한다.
**구현**: `src/ui/session.py`의 `SessionManager` 클래스. JSON 파일 1개 = 세션 1개.
**트레이드오프**: 멀티 PC 동기화 불가. 파일 시스템 접근 권한에 의존. 세션 파일이 장기간 누적되면 수동 정리 필요.

### ADR-014: 과거 세션 이어서 질문 불가 (읽기 전용)
**결정**: 과거 세션은 열람만 가능하며, 이어서 질문하려면 새 세션을 시작해야 한다.
**이유**: 과거 세션의 RAGEngine 메모리 완전 복원은 복잡도가 높고, 오래된 맥락이 새 질문의 Chain-1 응축에 오히려 방해가 될 수 있다.
**트레이드오프**: 며칠 전 대화를 이어가고 싶은 경우 불편함. 향후 "세션 이어가기" 기능으로 개선 가능.

### ADR-015: Reranking 미포함 (MVP 제외)
**결정**: 검색 후 재순위화(Reranking)는 MVP에서 제외한다.
**이유**: Pinecone 유사도 검색 + 임계값 0.7로 충분한 품질을 기대한다. 추가 시 외부 API 의존성, 비용, 응답 지연 증가.
**향후 개선**: 검색 품질이 불충분하다고 판단되면 Cohere Rerank API 또는 cross-encoder 로컬 모델 추가 가능.
